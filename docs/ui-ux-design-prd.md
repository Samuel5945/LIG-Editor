### 1.2 全局问题诊断（七类，按严重度）

1. **溢出与滚动条失控**：创作向导步进器 7 步横向溢出，挂一条又长又粗的灰色滚动条——全应用最扎眼的缺陷；各类胶囊条（分类筛选）存在折行堆叠问题
2. **图标语言不统一**：emoji（🌲📂🌞❓🎯📅✅❌）与线性图标混用，尺寸/粗细/亮度无规范
3. **状态语义不明**：工作树黄/蓝状态圆点无图例；步骤完成态用 emoji 对勾与圆圈混排
4. **信息层级弱**：中栏工作面裸文本平铺、大而无组织的留白；右栏工具调用日志以 ✅❌ 裸行平铺，调试感重
5. **控件形态各异**：同类操作有时是按钮、有时是浮块、有时是裸文字（审阅页「重新审阅/优化正文/开」）；开关无标签
6. **空态浪费**：未打开工程时中栏空壳，首屏零信息量
7. **能力入口隐蔽**：主题的三条来源（内置/导入/面板沉淀）分散无集中入口；「存为分类主题」藏在排版面板底部

## 2. 设计原则

1. **零失控滚动条**：任何横向条带（步骤、胶囊、页签）必须自适应收缩或单行横滑（隐藏滚动条+边缘渐隐），禁止裸露出系统粗滚动条；纵向滚动条一律细条（8px/6px）+  hover 加深
2. **一套图标**：全量线性 SVG（Lucide 风格），stroke-width=2；尺寸按场景三档（13/14/15px），emoji 只允许出现在用户内容里，不允许出现在 UI 上
3. **状态语义单源**：同一语义同一表达——步骤三态（完成/当前/未开始）、工程状态圆点（草稿黄/进行中蓝/已发布绿）全应用一致，且必须有图例或文字伴生，不靠猜
4. **主次分明**：一个视图一个主按钮（主色实心），次要操作描边，再次要幽灵；操作按语义归组右对齐，不游离
5. **空态即入口**：空状态必须给出下一步动作（封面墙、引导按钮、示例提示），不允许纯白
6. **改动可确认**：AI/Agent 的写操作结果一律卡片化呈现（结果卡/确认卡/diff），与主 PRD §10.2 的三层确认对齐

## 3. 设计系统 Tokens

### 3.1 色彩（日间；夜间反色由既有昼夜系统派生）

| 角色 | 值 | 用途 |
|---|---|---|
| primary | `#0D9488` / hover `#0F766E` | 主按钮、当前步骤、选中态、开启态 |
| primary-soft | `#E6F7F4` / softer `#F2FBF9` | 选中底色、光晕、toggle 底 |
| text-1/2/3 | `#1F2329` / `#5F6570` / `#959BA5` | 标题 / 正文 / 辅助 |
| border / border-soft | `#E4E7EB` / `#EEF0F3` | 强描边（输入框）/ 弱描边（卡片） |
| success / warning / info / danger | `#22A06B` / `#E8A13A` / `#4C88FF` / `#E5484D` | 状态与反馈 |
| bg / panel / panel-2 | `#F4F5F7` / `#FFFFFF` / `#FAFBFC` | 应用底 / 面板 / 次级面板 |

约束：状态圆点语义固定 黄=草稿、蓝=进行中、绿=已发布/完成，全应用（工作树、封面墙、看板、日历）不得另起颜色。

### 3.2 字号阶梯

15/700（报告标题）· 13.5/700（卡片标题）· 13/600（按钮）· 12.5/400（正文、树节点、气泡）· 11.5/400（辅助说明、步骤标签）· 10.5/400（时间戳、徽标）。界面字号小/中/大由 webFrame 缩放承载（既有能力），不在组件里写死第二套。

### 3.3 间距 / 圆角 / 阴影

- 间距 4 档：`4 / 8 / 12 / 16 / 24`；卡片内边距 18-20，卡片间距 14，树行高 28，控件高 30/32
- 圆角：控件 6 · 按钮/输入 8 · 卡片/弹窗 12 · 胶囊 999
- 阴影只有两级：卡片 `0 1px 6px rgba(31,35,41,.06)`；浮层/弹窗 `0 4px 16px rgba(31,35,41,.08)`；主按钮可带 `0 2px 6px rgba(13,148,136,.25)` 色阴影

### 3.4 动效

只做 150-200ms 的状态过渡（hover、选中、卡片浮起 translateY(-1~-2px)），不做装饰性动画；流式生成沿用渐显。

- **Tokens 单源**：落 `renderer/src/styles/tokens.ts`（或 CSS 变量表），组件禁写死色值；新增语义色先入 tokens 再使用——对齐主 PRD「口径单源」的一贯做法（THEME_OVERRIDE_KEYS 模式）
  - ✅ 2026-09-30 实落 **CSS 变量表**（`renderer/src/index.css` 的 `:root` / `:root.light`）：既有昼夜双主题已在此派生，另建 `tokens.ts` 会变成第二套口径。新增语义变量 `--st-draft/--st-doing/--st-done/--st-bad/--folder`，经 `tailwind.config.cjs` 暴露为 `bg-st-draft`/`text-st-bad`/`text-folder` 等类名，组件侧只写类名不写色值
- **组件先改壳后改瓤**：P0 批次的图标/按钮/胶囊先抽共享组件（Button/Chip/Stepper/StatusDot），逐界面替换，禁止各界面自造变体
  - ✅ 2026-09-30 共享控件单源落 `renderer/src/ui/`：`Icon.tsx`（24 视框、stroke-width=2、尺寸 13/14/15 三档的图标表）、`primitives.tsx`（Button/IconButton/Chip/ChipGroup/Stepper/StatusDot/StatusLegend/Switch/Card/CardTitle/EmptyState）、`status.ts`（工程状态 → 圆点语义单源，工作树与日历共用同一张表，禁各自另色）
  - 后续批次继续吃这条：新界面（封面墙/主题库）直接复用 `ChipGroup`/`StatusDot`/`Card`，不要再写内联样式变体
  - ⚠ **`Icon` 基类必须自带 `inline-block align-middle`**：Tailwind 预置把 `svg` 设成 `display:block`，
    图标一旦落在非 flex 容器（顶栏按钮、右键菜单行、行内徽标、错误提示 `<p>`）里就会被顶到文字上一行，
    且构建期零报错——P0 首版实测踩过（顶栏按钮高 37px＝两行）。容器是 flex 时该声明无副作用，
    所以统一在 `Icon` 一处解决，**不要**再往各调用点补 `align-[-2px]` 之类的补丁
